01

The Basics

Lira's syntax will feel familiar if you've used Rust, Go, or TypeScript. Let's start with variables, types, and functions.

Variables & Type Inference 
// Immutable by default with 'let'
let name = "Alice"          // type inferred as string
let age: int = 30           // explicit type annotation
let pi = 3.14159            // float
let active = true           // bool

// Mutable variables with 'var'
var counter = 0
counter = counter + 1       // OK: counter is mutable

// name = "Bob"             // ERROR: name is immutable

Use let for values that won't change (immutable) and var when you need mutation. The compiler infers types from the right-hand side, so you rarely need explicit annotations.

Functions 
// Function with typed parameters and return type
fn greet(name: string) -> string {
    return "Hello, " + name + "!"
}

// String concatenation with +
fn describe(name: string, age: int) -> string {
    return name + " is " + age + " years old"
}

// Functions without return value
fn log(message: string) {
    println("[LOG] " + message)
}

// Call functions
let message = greet("World")
println(message)  // Hello, World!

Functions use the fn keyword. Parameter types are required, but the return type can often be inferred. Use + for string concatenation.

Control Flow 
// If expressions (not statements!)
let status = if age >= 18 { "adult" } else { "minor" }

// Traditional if/else
if score >= 90 {
    println("Excellent!")
} else if score >= 70 {
    println("Good")
} else {
    println("Keep trying")
}

// For-in loops iterate over arrays
let items = [10, 20, 30]
for item in items {
    println(item)  // 10, 20, 30
}

// While loops for counting
var i = 0
while i < 5 {
    println(i)  // 0, 1, 2, 3, 4
    i = i + 1
}

// Ranges create range objects (not for iteration)
let r = 1..10         // exclusive: 1 to 9
let ri = 1..=10       // inclusive: 1 to 10

In Lira, if is an expression that returns a value. Use for-in to iterate arrays and while for counted loops.

02

Structs & Methods

Model your domain with structs. Add behavior with methods in impl blocks.

The Problem

We're building a task runner. We need to represent tasks with a name, status, and priority.

Defining Structs 
struct Task {
    name: string
    priority: int
    completed: bool
}

// Create instances with struct literals
let task = Task {
    name: "Write documentation",
    priority: 2,
    completed: false
}

// Access fields
println(task.name)       // Write documentation
println(task.priority)   // 2
Adding Methods with impl 
struct Task {
    name: string
    priority: int
    completed: bool
}

impl Task {
    // Static method (no self) - constructor pattern
    fn new(name: string, priority: int) -> Task {
        return Task {
            name: name,
            priority: priority,
            completed: false
        }
    }

    // Instance method (takes self)
    fn describe(self) -> string {
        let status = if self.completed { "✓" } else { "○" }
        return status + " [P" + self.priority + "] " + self.name
    }

    // Method returning new instance (immutable pattern)
    fn complete(self) -> Task {
        return Task {
            name: self.name,
            priority: self.priority,
            completed: true
        }
    }

    fn is_high_priority(self) -> bool {
        return self.priority >= 3
    }
}

// Usage
let task = Task.new("Deploy to production", 5)
println(task.describe())   // ○ [P5] Deploy to production

let done = task.complete()
println(done.describe())   // ✓ [P5] Deploy to production

The impl block separates data (struct fields) from behavior (methods). Static methods like new() are called on the type (Task.new()), while instance methods take self and are called on values (task.describe()).

03

Enums & Pattern Matching

Enums in Lira can carry data. Combined with pattern matching, they're perfect for representing states and handling variants.

Simple Enums 
enum TaskStatus {
    Pending,
    Running,
    Completed,
    Failed
}

let status = TaskStatus::Running

// Pattern match on enum
match status {
    TaskStatus::Pending => println("Waiting to start"),
    TaskStatus::Running => println("In progress..."),
    TaskStatus::Completed => println("Done!"),
    TaskStatus::Failed => println("Something went wrong")
}
Enums with Data 
// Enums can carry different data per variant
enum TaskResult {
    Success(string),          // carries output message
    Failure(string, int)     // carries error message and code
}

fn run_task(name: string) -> TaskResult {
    if name == "risky" {
        return TaskResult::Failure("Task crashed", 1)
    }
    return TaskResult::Success("Completed: ${name}")
}

// Extract data with pattern matching
let result = run_task("build")

match result {
    TaskResult::Success(msg) => {
        println("✓ ${msg}")
    }
    TaskResult::Failure(msg, code) => {
        println("✗ ${msg} (exit code: ${code})")
    }
}

Pattern matching on enums with data lets you destructure and extract values in one step. The compiler ensures you handle all variants.

The Option Type 
// Option represents a value that might not exist
enum Option {
    None,
    Some(T)    // generic over any type T
}

fn find_task(tasks: [Task], name: string) -> Option {
    for task in tasks {
        if task.name == name {
            return Option::Some(task)
        }
    }
    return Option::None
}

// Handle the Option
match find_task(tasks, "deploy") {
    Option::Some(task) => println("Found: " + task.name),
    Option::None => println("Task not found")
}

Instead of null, Lira uses Option to explicitly represent values that might be absent. This eliminates null pointer errors at compile time.

04

Error Handling

Lira uses the Result type for operations that can fail. The ? operator makes error propagation clean.

The Result Type 
// Result represents success or failure
fn divide(a: int, b: int) -> Result<int, string> {
    if b == 0 {
        return Result::Err("division by zero")
    }
    return Result::Ok(a / b)
}

// Handle with pattern matching
match divide(10, 2) {
    Result::Ok(value) => println("Result: " + value),
    Result::Err(msg) => println("Error: " + msg)
}
The ? Operator 
// Without ? - verbose error handling
fn calculate_verbose(a: int, b: int) -> Result<int, string> {
    let r1 = divide(a, b)
    match r1 {
        Result::Err(e) => return Result::Err(e),
        Result::Ok(v1) => {
            let r2 = divide(v1, 2)
            match r2 {
                Result::Err(e) => return Result::Err(e),
                Result::Ok(v2) => return Result::Ok(v2 * 10)
            }
        }
    }
}

// With ? - clean and concise!
fn calculate(a: int, b: int) -> Result<int, string> {
    let v1 = divide(a, b)?       // Returns Err early if fails
    let v2 = divide(v1, 2)?      // Same here
    return Result::Ok(v2 * 10)  // Only reached if both succeed
}

The ? operator unwraps a Result: if it's Ok, you get the value; if it's Err, the error is returned immediately. This eliminates error handling boilerplate.

05

Collections

Lira provides lists, maps, and sets with functional methods like map, filter, and reduce.

Arrays & Iteration 
// Create arrays
let numbers = [1, 2, 3, 4, 5]
let names = ["alice", "bob", "charlie"]

// Access elements
println(numbers[0])       // 1
println(len(names))       // 3

// Iterate with for-in
for n in numbers {
    println(n * 2)
}

// Sum elements
var total = 0
for n in numbers {
    total = total + n
}
println(total)  // 15

// Mutate with push/pop
let stack = []
push(stack, 1)
push(stack, 2)
push(stack, 3)
let top = pop(stack)  // 3
Lambdas & Higher-Order Functions 
// Lambda syntax uses |args| body
let double = |x: int| x * 2
let add = |a: int, b: int| a + b

println(double(5))    // 10
println(add(3, 4))    // 7

// Functions that take functions as parameters
fn apply_twice(f: fn(int) -> int, x: int) -> int {
    return f(f(x))
}

println(apply_twice(double, 3))  // 12

// Closures capture outer variables
fn make_adder(n: int) -> fn(int) -> int {
    return |x: int| x + n
}

let add5 = make_adder(5)
println(add5(10))  // 15

Lambdas use |args| expression syntax. They can capture variables from outer scopes, making closures easy to create.

06

Generics

Write code that works with any type. Generics are checked at compile time for type safety.

Generic Functions & Structs 
// Generic identity function
fn identity<T>(value: T) -> T {
    return value
}

println(identity(42))        // 42 (T = int)
println(identity("hello"))   // hello (T = string)

// Generic wrapper struct
struct Box<T> {
    value: T
}

impl Box<T> {
    fn unwrap(self) -> T {
        return self.value
    }

    fn map<U>(self, f: fn(T) -> U) -> Box<U> {
        return Box { value: f(self.value) }
    }
}

let int_box = Box { value: 100 }
let str_box = int_box.map(|n: int| "value: " + n)
println(str_box.unwrap())  // value: 100

Type parameters in angle brackets <T> make functions and structs work with any type. The compiler infers concrete types from usage.

07

Concurrency with Fibers

Fibers are lightweight green threads. Spawn thousands of concurrent tasks without the overhead of OS threads.

The Problem

Our task runner needs to execute multiple tasks concurrently. We want to start them all, then wait for results.

Spawning Fibers 
// Define worker functions
fn worker(id: int) {
    println("Worker " + id + " running")
    sleep(100)
    println("Worker " + id + " done")
}

fn compute(a: int, b: int) -> int {
    return a + b
}

fn main() {
    println("Starting tasks...")

    // Spawn concurrent fibers
    spawn worker(1)
    spawn worker(2)
    spawn worker(3)

    // Spawn a computation
    spawn compute(10, 20)

    println("All fibers spawned")
}

spawn starts a function call in a new fiber that runs concurrently. The main fiber continues immediately without waiting. Fibers are lightweight - you can spawn thousands.

Concurrent Task Pattern 
// Use channels to collect results from fibers
fn run_task(name: string, results: channel) {
    println("Running: " + name)
    sleep(100)
    send(results, name + " complete")
}

fn main() {
    let results = chan(3)  // buffered channel

    // Spawn tasks that send results to channel
    spawn run_task("build", results)
    spawn run_task("test", results)
    spawn run_task("deploy", results)

    // Collect all results
    var count = 0
    while count < 3 {
        let result = recv(results)
        println(result)
        count = count + 1
    }
}

Channels let fibers communicate results back to the main fiber. This pattern runs all tasks concurrently - total time is the slowest task, not the sum.

08

Channels

Channels provide safe communication between fibers. No shared mutable state means no data races.

Basic Channel Usage 
// Create channels with chan(buffer_size)
let ch = chan(5)  // buffered channel, capacity 5

// send(channel, value) - sends a value
send(ch, 42)
send(ch, 100)

// recv(channel) - receives a value (blocks if empty)
let first = recv(ch)   // 42
let second = recv(ch)  // 100

// close(channel) - signals no more values
close(ch)
Producer-Consumer Pattern 
// Producer sends values to channel
fn producer(ch: channel, count: int) {
    var i = 1
    while i <= count {
        println("Sending: " + i)
        send(ch, i * i)
        i = i + 1
    }
}

fn main() {
    let results = chan(10)
    
    // Producer runs in separate fiber
    spawn producer(results, 5)
    
    // Consumer in main fiber
    var total = 0
    var count = 0
    while count < 5 {
        let value = recv(results)
        println("Received: " + value)
        total = total + value
        count = count + 1
    }
    println("Sum of squares: " + total)  // 55
}

Channels safely transfer data between fibers. send and recv block when needed, making concurrent code straightforward to write.

09

File I/O & JSON

Lira's standard library includes modules for file operations, JSON parsing, HTTP, and more.

Reading & Writing Files 
// Check if file exists
if file_exists("/tmp/tasks.json") {
    println("Found existing tasks")
}

// Write to file
let fd = file_open("/tmp/output.txt", 1)  // 1 = write mode
file_write(fd, "Task results:\n")
file_write(fd, "- build: success\n")
file_write(fd, "- test: success\n")
file_close(fd)

// Read from file
let fd = file_open("/tmp/output.txt", 0)  // 0 = read mode
let content = file_read(fd, 1024)
println(content)
file_close(fd)
JSON Parsing 
// Parse JSON string
let data = json_parse("{\"name\": \"deploy\", \"priority\": 5}")
println(data["name"])      // deploy
println(data["priority"])  // 5

// Parse arrays
let tasks = json_parse("[{\"name\": \"a\"}, {\"name\": \"b\"}]")
for task in tasks {
    println(task["name"])
}

// Convert back to JSON string
let json_str = json_stringify(data)
println(json_str)

// Pretty print with indentation
println(json_pretty(data))

Built-in JSON functions make it easy to work with configuration files, API responses, and data storage.

10

Putting It Together

Let's combine everything into a complete concurrent task runner.

Complete Task Runner 
// task_runner.li - A concurrent task execution system

enum TaskResult {
    Success(string),
    Failure(string)
}

struct Task {
    name: string
    priority: int
}

fn new_task(name: string, priority: int) -> Task {
    return Task { name: name, priority: priority }
}

fn run_task(task: Task, results: channel) {
    println("[START] " + task.name)
    sleep(50 + task.priority * 10)
    
    if task.name == "flaky" {
        send(results, TaskResult::Failure(task.name))
    } else {
        send(results, TaskResult::Success(task.name))
    }
}

fn print_result(result: TaskResult) {
    match result {
        TaskResult::Success(name) => println("✓ " + name)
        TaskResult::Failure(name) => println("✗ " + name)
    }
}

fn main() {
    let tasks = [
        new_task("build", 3),
        new_task("test", 2),
        new_task("lint", 1),
        new_task("deploy", 5)
    ]
    
    let results = chan(len(tasks))
    
    println("Running " + len(tasks) + " tasks concurrently...")
    let start = time_ms()
    
    // Spawn all tasks
    for task in tasks {
        spawn run_task(task, results)
    }
    
    // Collect results
    println("")
    println("=== Results ===")
    var i = 0
    while i < len(tasks) {
        let result = recv(results)
        print_result(result)
        i = i + 1
    }
    
    let elapsed = time_ms() - start
    println("")
    println("Wall clock time: " + elapsed + "ms")
}

main()

This complete example demonstrates structs, enums, pattern matching, channels, and fibers working together. All tasks run concurrently, so total time is dominated by the slowest task rather than the sum of all tasks.
