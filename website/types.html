01

Primitive Types

Lira has a small set of built-in types that form the foundation for all data.

Numeric Types 
// Integer - 64-bit signed
let age: int = 30
let negative: int = -42
let big: int = 9223372036854775807

// Float - 64-bit IEEE 754
let pi: float = 3.14159
let scientific: float = 1.5e10

// Arithmetic operations
let sum = 10 + 5      // 15
let diff = 10 - 5     // 5
let prod = 10 * 5     // 50
let quot = 10 / 3     // 3 (integer division)
let rem = 10 % 3      // 1 (remainder)
let power = 2 ** 10   // 1024 (exponentiation)
Boolean Type 
let active: bool = true
let disabled: bool = false

// Logical operators
let both = true && true    // true
let either = true || false  // true
let not_active = !active     // false

// Comparison operators return bool
let equal = 5 == 5          // true
let not_equal = 5 != 3      // true
let less = 3 < 5            // true
let greater = 5 > 3         // true
String Type 
let greeting: string = "Hello, World!"
let empty: string = ""

// String concatenation
let name = "Alice"
let message = "Hello, " + name + "!"  // "Hello, Alice!"

// String length
println(len(greeting))  // 13

// Escape sequences
let newline = "Line 1\nLine 2"
let tab = "Col1\tCol2"
let quote = "She said \"Hi\""
let backslash = "C:\\path\\file"
02

Type Inference

Lira's compiler infers types from context, so you rarely need explicit annotations. The compiler always knows the exact type.

Inferred Variables 
// Type inferred from right-hand side
let count = 42          // int
let price = 19.99       // float
let name = "Bob"        // string
let active = true       // bool
let items = [1, 2, 3]   // [int]

// Explicit annotations still work
let explicit: int = 42  // Same as above

The compiler infers count is int because 42 is an integer literal. You can add annotations for documentation or to resolve ambiguity.

Inferred Function Returns 
// Return type can be inferred
fn double(x: int) -> int {
    return x * 2
}

// Parameter types are always required
fn greet(name: string) -> string {
    return "Hello, " + name
}

fn main() {
    // Result type inferred from function
    let result = double(21)   // int
    let msg = greet("World")  // string

    println(result)
    println(msg)
}

main()

Function parameters must have explicit types - they're the interface others call. Return types and local variables can be inferred.

When to Annotate 
// Empty collections need type hints
let empty_ints: [int] = []
let empty_strings: [string] = []

// Numeric literals without context
let zero_int: int = 0
let zero_float: float = 0.0

// For documentation / clarity
let user_id: int = get_user_id()

Add annotations when the type can't be inferred (empty collections) or when it improves code readability.

03

Collection Types

Lira provides arrays and tuples for grouping values.

Arrays 
// Homogeneous - all elements same type
let numbers: [int] = [1, 2, 3, 4, 5]
let names: [string] = ["Alice", "Bob", "Charlie"]

// Access by index (0-based)
println(numbers[0])   // 1
println(numbers[2])   // 3

// Length
println(len(numbers))  // 5

// Nested arrays
let matrix: [[int]] = [
    [1, 2, 3],
    [4, 5, 6],
    [7, 8, 9]
]
println(matrix[1][1])  // 5

// Iteration
for n in numbers {
    println(n)
}
Array Operations 
let stack = []

// push adds to end
push(stack, 1)
push(stack, 2)
push(stack, 3)
println(stack)  // [1, 2, 3]

// pop removes from end
let top = pop(stack)
println(top)    // 3
println(stack)  // [1, 2]
Tuples 
// Heterogeneous - different types allowed
let pair: (int, string) = (42, "answer")
let triple: (int, float, bool) = (1, 2.5, true)

// Tuples are fixed-size
let point = (10, 20)
let rgb = (255, 128, 0)

// Return multiple values
fn divide_rem(a: int, b: int) -> (int, int) {
    return (a / b, a % b)
}

let result = divide_rem(17, 5)
println(result)  // (3, 2)

Unlike arrays, tuples can contain different types. They're useful for returning multiple values or grouping related but differently-typed data.

04

Function Types

Functions are first-class values in Lira. You can pass them around, store them in variables, and return them from other functions.

Function Type Syntax 
// fn(param_types) -> return_type

// Takes int, returns int
let double: fn(int) -> int = |x: int| x * 2

// Takes two ints, returns int
let add: fn(int, int) -> int = |a: int, b: int| a + b

// Takes nothing, returns int
let get_ten: fn() -> int = || 10

fn main() {
    println(double(21))    // 42
    println(add(3, 4))     // 7
    println(get_ten())    // 10
}

main()
Higher-Order Functions 
// Function that takes a function as parameter
fn apply_twice(f: fn(int) -> int, x: int) -> int {
    return f(f(x))
}

fn double(n: int) -> int {
    return n * 2
}

fn main() {
    let result = apply_twice(double, 3)
    println(result)  // 12 (3*2*2)

    // With lambda
    let result2 = apply_twice(|x: int| x + 10, 0)
    println(result2)  // 20
}

main()
Functions Returning Functions 
// Factory function - returns a function
fn make_adder(n: int) -> fn(int) -> int {
    return |x: int| x + n
}

fn make_multiplier(n: int) -> fn(int) -> int {
    return |x: int| x * n
}

fn main() {
    let add5 = make_adder(5)
    let add10 = make_adder(10)
    let triple = make_multiplier(3)

    println(add5(3))    // 8
    println(add10(3))   // 13
    println(triple(7))  // 21
}

main()

The lambda captures the parameter n from its enclosing scope. Each call to make_adder creates a new closure with its own captured value.

05

Generics

Write code that works with any type using type parameters. The compiler checks types at compile time.

Generic Functions 
// T is a type parameter
fn identity<T>(value: T) -> T {
    return value
}

fn main() {
    // T inferred from argument
    let a = identity(42)        // T = int
    let b = identity("hello")   // T = string
    let c = identity(true)      // T = bool

    println(a)  // 42
    println(b)  // hello
    println(c)  // true
}

main()

The <T> declares a type parameter. The compiler substitutes concrete types when the function is called, ensuring type safety.

Multiple Type Parameters 
// Two type parameters
fn pair<A, B>(first: A, second: B) -> (A, B) {
    return (first, second)
}

fn main() {
    let p1 = pair(1, "one")      // (int, string)
    let p2 = pair(true, 3.14)    // (bool, float)

    println(p1)  // (1, "one")
    println(p2)  // (true, 3.14)
}

main()
Generic Structs 
struct Box<T> {
    value: T
}

impl Box<T> {
    fn unwrap(self) -> T {
        return self.value
    }

    fn map<U>(self, f: fn(T) -> U) -> Box<U> {
        return Box { value: f(self.value) }
    }
}

fn main() {
    let int_box = Box { value: 42 }
    println(int_box.unwrap())  // 42

    let str_box = Box { value: "hello" }
    println(str_box.unwrap())  // hello

    // Transform the boxed value
    let doubled = Box { value: 10 }.map(|n: int| n * 2)
    println(doubled.unwrap())  // 20
}

main()

Generic structs can hold any type. The map method shows how generics compose - it transforms Box<T> into Box<U> using a function fn(T) -> U.

06

Optional Types

Lira uses optional types to handle values that might not exist, eliminating null pointer errors.

Optional Type Syntax 
// ? suffix marks a type as optional
fn find_index(arr: [int], target: int) -> int? {
    var i = 0
    while i < len(arr) {
        if arr[i] == target {
            return i
        }
        i = i + 1
    }
    return null
}

fn main() {
    let numbers = [10, 20, 30, 40]

    let found = find_index(numbers, 30)
    let missing = find_index(numbers, 99)

    println(found)    // 2
    println(missing)  // null
}

main()

The ? suffix indicates a type that can be null. Regular types can't be null - the compiler enforces this.

Null Coalescing (??) 
fn main() {
    let value: int? = null
    let some_value: int? = 42

    // ?? provides a default if null
    let a = value ?? 0
    let b = some_value ?? 0

    println(a)  // 0 (value was null)
    println(b)  // 42 (some_value was not null)

    // Chaining
    let first: int? = null
    let second: int? = null
    let third: int? = 99

    let result = first ?? second ?? third ?? 0
    println(result)  // 99
}

main()
Optional Chaining (?.) 
struct Person {
    name: string
    age: int
}

fn main() {
    let person: Person? = Person { name: "Alice", age: 30 }
    let nobody: Person? = null

    // ?. safely accesses fields on optional
    println(person?.name)   // Alice
    println(nobody?.name)   // null (no error)
}

main()

The ?. operator short-circuits if the left side is null, returning null instead of causing an error. This makes null handling concise and safe.

Try Operator (?) 
fn get_config_value() -> int? {
    return 42
}

fn process() -> int? {
    // ? unwraps or returns null early
    let value = get_config_value()?
    return value * 2
}

fn main() {
    let result = process()
    println(result)  // 84
}

main()

The ? operator unwraps an optional. If it's null, the function returns null immediately. Otherwise, the unwrapped value is used.

07

Result Type

Use Result for operations that can fail with an error message, not just absence of a value.

Defining Result 
enum Result<T, E> {
    Ok(T),
    Err(E)
}

fn parse_int(s: string) -> Result<int, string> {
    if s == "42" {
        return Result::Ok(42)
    }
    return Result::Err("Invalid number: " + s)
}

fn main() {
    let good = parse_int("42")
    let bad = parse_int("abc")

    match good {
        Result::Ok(n) => println("Parsed: " + n),
        Result::Err(e) => println("Error: " + e)
    }

    match bad {
        Result::Ok(n) => println("Parsed: " + n),
        Result::Err(e) => println("Error: " + e)
    }
}

main()
Error Propagation 
fn divide(a: int, b: int) -> Result<int, string> {
    if b == 0 {
        return Result::Err("division by zero")
    }
    return Result::Ok(a / b)
}

fn compute(a: int, b: int, c: int) -> Result<int, string> {
    // ? propagates errors automatically
    let x = divide(a, b)?
    let y = divide(x, c)?
    return Result::Ok(y)
}

fn main() {
    let r1 = compute(100, 10, 2)  // Ok(5)
    let r2 = compute(100, 0, 2)   // Err("division by zero")
    let r3 = compute(100, 10, 0)  // Err("division by zero")

    match r1 {
        Result::Ok(v) => println("r1 = " + v),
        Result::Err(e) => println("r1 error: " + e)
    }

    match r2 {
        Result::Ok(v) => println("r2 = " + v),
        Result::Err(e) => println("r2 error: " + e)
    }
}

main()

The ? operator on Result unwraps Ok values or returns the Err early. This makes error handling concise without hiding the error paths.
